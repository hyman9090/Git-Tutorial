Git 完全教學

常用指令、旗標（flag）變化、Before / After 圖解一次過睇晒。由 git init 到 git rebase -i，照住做就得。

閱讀方式 每個指令都會有：用途簡介 → 語法 → 常用 flag 對照表 → 範例 → 圖解（如適用）。 灰色圓點係普通 commit，藍色係 main、綠色係 feature、橙色係 hotfix，虛線圓圈代表「將會被移除/覆蓋」嘅狀態。

基本概念（必讀）#

學 Git 指令之前，一定要搞清楚 Git 嘅「三個區域」同「HEAD」。之後所有指令，其實都係喺呢幾個區域之間搬嘢。

1. 三個區域（加埋遠端就四個）

2. 檔案嘅四種狀態

3. HEAD 係咩？

HEAD 係一個指標，指向「你而家企緊嘅位置」— 通常指向某個 branch，而 branch 再指向某個 commit。

普通 commit 分支最新 commit（分支指標位置） 將被移除 / 覆蓋

取得幫助：-h / --help#

唔記得某個指令點用？Git 內建咗兩層 help，每一個子指令都支援。

-h vs --help 分別

寫法輸出幾時用
git <指令> -h喺 terminal 直接列出簡短選項清單想快速睇有咩 flag 可用
git <指令> --help打開完整 man page 說明文件（瀏覽器或 pager）想睇詳細解釋同範例
git help <指令>同 --help 一樣另一種寫法，效果相同
bash
# 快速睇 commit 有咩選項（喺 terminal 即刻顯示）
git commit -h

# 打開 commit 嘅完整手冊
git commit --help
git help commit

# 列出所有 git 指令
git help -a

# 列出 git 概念指南（例如 git help everyday、giteveryday(7)）
git help -g

# 睇 git 版本
git version
貼士想知 -v、-f、-n 呢啲短 flag 喺某指令度代表咩，最快係打 git <指令> -h。留意：同一個字母喺唔同指令可以係完全唔同意思（例如 git tag -v 係驗證簽名，git branch -v 係顯示詳情，git remote -v 係顯示 URL）。

git config — 設定身份同偏好#

第一次用 Git 必先設定用戶名同 email，否則 commit 唔到（或 commit 咗啲奇怪身份）。

語法

bash
# 第一次必做（--global 對呢部電腦你所有 repo 生效）
git config --global user.name "Chan Tai Man"
git config --global user.email "taiman@example.com"

# 預設分支名用 main
git config --global init.defaultBranch main

# 預設編輯器（寫 commit message 用）
git config --global core.editor "code --wait"

# 開彩色輸出
git config --global color.ui auto

三個層級（local 優先 > global > system）

Flag設定檔位置適用範圍
--system系統 git 安裝目錄整部機所有用戶所有 repo
--global~/.gitconfig你呢個用戶嘅所有 repo（最常用）
--local（預設）.git/config（單一 repo 內）淨係呢個 repo，會覆蓋 global

常用 flag

Flag作用例子
--list / -l列出所有設定git config --list
--list --show-origin列出設定＋嚟自邊個檔案搵緊某設定喺邊度嚟時超好用
--get讀取單一值git config --get user.name
--unset刪除某項設定git config --global --unset core.editor
--edit / -e用編輯器打開設定檔直接改git config --global -e
--add新增一項（可重複 key）git config --add alias.lg "log --oneline"

Alias（指令縮寫）— 高手必備

bash
git config --global alias.st status
git config --global alias.co checkout
git config --global alias.br branch
git config --global alias.cm "commit -m"
git config --global alias.lg "log --oneline --graph --decorate --all"
git config --global alias.undo "reset --soft HEAD~1"

# 之後就可以直接咁用：
git st
git lg
注意公司 repo 想唔同身份？入到個 repo 度用 git config user.email "work@company.com"（唔加 --global，即 --local），淨係影響嗰個 repo。

git init / git clone — 建立或複製倉庫#

開始一個 repo 得兩條路：本地全新開一個（init），或者由遠端複製一個返嚟（clone）。

1git init — 喺而家目錄初始化 repo

bash
mkdir my-project && cd my-project
git init                    # 喺而家目錄建立 .git/
git init my-project         # 建一個新資料夾兼喺入面 init
git init -b main            # 指定初始分支名（Git ≥ 2.28）
Flag作用
-b <名> / --initial-branch=<名>指定第一個分支名（例：main）
--bare建立「裸倉庫」（冇工作目錄，淨係攞嚟做中央伺服器 repo，通常叫 xxx.git）
--quiet / -q靜音模式，唔輸出訊息
注意喺已經係 repo 嘅目錄再 git init 係安全嘅，唔會刪走任何嘢，只會補返缺失嘅結構。

2git clone — 由遠端複製成個 repo 返本地

bash
git clone https://github.com/user/repo.git            # 複製到 ./repo
git clone https://github.com/user/repo.git my-folder  # 複製到自訂資料夾名
git clone git@github.com:user/repo.git                # SSH 版（設好 SSH key 後用）
Flag作用例子
--depth <n>淺複製：只拎最近 n 個 commit，快好多、慳位（代價：冇完整歷史）git clone --depth 1 <url>
-b <分支> / --branchclone 完直接 checkout 指定分支或 taggit clone -b dev <url>
--single-branch只複製一個分支（通常連 --depth 一齊用）git clone --depth 1 --single-branch -b main <url>
--recurse-submodules連 submodule 一齊初始化同更新repo 有 submodule 時必加
-o <名> / --origin遠端名唔用預設嘅 origin，改用自訂名git clone -o upstream <url>
--mirror鏡像複製（連所有 ref 原封不動，做備份/搬伺服器用）git clone --mirror <url>
-v / --verbose顯示更詳細過程
-q / --quiet靜音

日常快照：status / add / commit / diff / rm / mv#

呢六個指令係你每日會用幾十次嘅核心循環：改嘢 → 睇狀態 → 暫存 → 提交。

1git status — 睇而家嘅狀態

bash
git status          # 完整版（新手友善，會提示你下一步可以做咩）
git status -s       # 精簡版，一個檔案一行
git status -sb      # 精簡版＋第一行顯示分支同領先/落後資訊
Flag作用
-s / --short精簡輸出，用兩個字母（XY）表示狀態
-b / --branch連分支資訊一齊顯示（配 -s 用：-sb）
-u<模式>未追蹤檔案顯示方式：-unormal（預設）、-uall（逐個列出）、-uno（唔顯示）
--ignored連被 .gitignore 忽略嘅檔案都列出嚟
--porcelain機器可讀格式（寫 script 用）
-v / --verbose連已暫存嘅 diff 內容都顯示埋

-s 精簡版嘅 XY 代碼點睇

bash
$ git status -s
 M index.html     # 第2位 M：工作目錄改咗，未 add
M  style.css      # 第1位 M：已 add，未 commit
MM app.js         # 已 add 之後又再改過
A  new-file.txt   # A：新加入暫存區
D  old.txt        # 已刪除（已暫存）
?? notes.md       # ??：untracked 新檔案

第一個字母＝暫存區狀態（同 HEAD 比），第二個字母＝工作目錄狀態（同暫存區比）。

2git add — 將改動放入暫存區

➜
bash
git add a.js              # 加一個檔案
git add a.js b.js c.js    # 加多個檔案
git add .                 # 加目前目錄及子目錄所有改動
git add src/              # 加成個資料夾
git add '*.js'            # 用萬用字元（要加引號）
Flag作用
-A / --all加晒全部改動（包括刪除檔案），不限目前目錄
-u / --update只 add 已追蹤檔案嘅修改同刪除，唔理 untracked 新檔
-p / --patch互動模式：逐塊（hunk）揀 add 唔 add，精細控制
-n / --dry-run假裝執行：顯示會加咩，但唔真係加
-f / --force強制 add 被 .gitignore 忽略嘅檔案
-v / --verbose顯示每個被加入嘅檔案

git add -p 互動模式按鍵

按鍵意思按鍵意思
y要呢一塊n唔要呢一塊
s再拆細呢一塊（split）e手動編輯呢一塊
a呢個檔案剩餘全部要d呢個檔案剩餘全部唔要
q退出?幫助

3git commit — 將暫存區快照寫入歷史

bash
git commit                          # 打開編輯器寫 message
git commit -m "修正登入按鈕樣式"      # 直接俾 message（最常用）
git commit -m "標題" -m "詳細內容"   # 多個 -m = 分段（標題＋內文）
git commit -am "訊息"               # add 已追蹤檔案＋commit 一步到位
Flag作用
-m "<訊息>"直接提供 commit message，唔開編輯器
-a / --all自動 add 晒已追蹤檔案嘅修改同刪除先 commit（untracked 新檔唔包）
--amend修改上一個 commit（加漏嘢、改 message 用；會改寫歷史）
--no-edit配合 --amend 用：保留原有 message 唔改
--author="名 <email>"指定作者係其他人
--date="<日期>"自訂 commit 日期（如 "2024-01-15 10:00"）
--allow-empty冇任何改動都照 commit（做標記、觸發 CI 用）
-n / --no-verify跳過 pre-commit hook（例如 lint 擋住想強行 commit）
-s / --signoff訊息尾加 Signed-off-by 行
-v / --verbose喺編輯器底部顯示完整 diff，方便寫 message
-q / --quiet靜音

--amend 圖解：改寫最後一個 commit

➜

舊 commit C 被新 commit C' 取代（hash 會變）。虛線 C 變成冇分支指向嘅「孤兒」。

危險--amend 會改寫歷史：已經 push 咗嘅 commit 千祈唔好 amend，否則隊友 pull 時會撞車。只可以 amend 未公開嘅 commit。

好嘅 commit message 格式

text
feat: 新增會員註冊功能        ← 第一行：50字內講「做咗咩」（祈使句）
                              ← 空一行
- 加入註冊表單同驗證           ← 內文：講「點解」同「點做」
- 密碼用 bcrypt 加密

Closes #123                   ← 關聯 issue

4git diff — 睇改咗啲咩

最緊要記住：diff 比較邊兩樣嘢，完全取決於你點落參數。

bash
git diff                      # 工作目錄 vs 暫存區（未 add 嘅改動）
git diff --staged             # 暫存區 vs HEAD（已 add、將會 commit 嘅嘢）
git diff HEAD                 # 工作目錄 vs HEAD（全部未 commit 改動）
git diff a.js                 # 淨係睇一個檔案
git diff HEAD~3 HEAD          # 兩個 commit 之間
git diff main                 # 而家分支 vs main
git diff main..feature        # 同上（兩點寫法）
git diff main...feature       # 三點：feature 自分支出嚟之後改咗咩（推薦）
Flag作用
--staged / --cached比較暫存區同 HEAD（兩個名一樣意思）
--stat淨係睇摘要：邊個檔案改咗幾多行
--name-only只列檔名
--name-status檔名＋狀態（M/A/D）
-w / --ignore-all-space忽略空白差異（改縮排嗰陣特別有用）
--word-diff以「字」為單位顯示差異（文件類檔案好用）
-U<n>差異上下多顯示 n 行 context（如 -U10）
--color-words逐字上色顯示差異

5git rm / git mv — 刪除同改名

bash
git rm old.txt                # 刪除檔案＋暫存呢個刪除（一步搞掂）
git rm --cached secret.env    # 停止追蹤，但保留硬碟上嘅檔案
git rm -r --cached node_modules/   # 成個資料夾停止追蹤（誤 add 後補救）
git mv old-name.js new-name.js     # 改名＋暫存（等於 mv + git rm + git add）
Flag作用
--cached只喺 Git 度移除追蹤，硬碟檔案保留（配 .gitignore 補救最常用）
-f / --force強制刪除（檔案有未暫存改動時 Git 會阻止，-f 硬闖）
-r遞迴：成個資料夾一齊刪
-n / --dry-run預演：顯示會刪咩，唔真係刪
--ignore-unmatch檔案唔存在都唔報錯（script 用）
-q靜音
貼士典型補救流程：誤 commit 咗 .env → 先寫入 .gitignore → git rm --cached .env → commit。檔案仲喺你部機度，但 Git 唔再追蹤。

git mv 都支援 -f（覆蓋已存在檔案）、-n（dry run）、-v（verbose）、-k（出錯時跳過繼續）。

檢視歷史：git log / git show / git blame / git reflog#

Git 嘅歷史就係佢嘅靈魂。學識睇歷史，你先可以喺幾百個 commit 入面搵到你要嘅嘢。

1git log — 睇 commit 歷史

bash
git log                                   # 完整歷史（q 退出）
git log --oneline                         # 一行一個 commit（極常用）
git log --oneline -10                     # 淨係最近 10 個
git log --graph --oneline --decorate --all  # 畫出分支圖（強烈建議做 alias）

篩選類 flag

Flag作用例子
-<n> / -n <n> / --max-count=<n>只顯示最近 n 個git log -5
--since / --after某時間之後git log --since="2 weeks ago"
--until / --before某時間之前git log --until="2024-06-01"
--author="<名>"篩作者（支援部分匹配）git log --author="Tai Man"
--grep="<字>"篩 message 內容git log --grep="fix"
-S"<字>"（pickaxe）篩「程式碼入面出現/消失咗某字串」嘅 commitgit log -S"password" --oneline
-G"<regex>"同上但用正則git log -G"api_key.*="
-- <路徑>只睇某檔案/資料夾嘅歷史git log --oneline -- src/app.js
--follow追蹤改名過嘅檔案（要配 -- <檔案>）git log --follow -p -- app.js
--merges / --no-merges只睇 / 唔睇 merge commitgit log --no-merges
--first-parent只行主線，唔入分支（main 乾淨好多）git log --first-parent --oneline
A..B喺 B 有、但 A 冇嘅 commitgit log main..feature --oneline
--all所有分支嘅歷史
--reverse反轉順序（最舊先）

顯示格式類 flag

Flag作用
--oneline= --pretty=oneline --abbrev-commit，一行一個
--graph左邊畫 ASCII 分支線
--decorate顯示分支/tag 名喺邊個 commit
-p / --patch每個 commit 連完整 diff
--stat每個 commit 顯示改動檔案統計
--shortstat只顯示總行數統計
--name-only / --name-status列出改動檔名
--abbrev-commithash 縮短顯示
--pretty=format:"..."自訂格式（見下表）

--pretty=format: 常用佔位符

符號意思符號意思
%h / %H短 / 長 hash%an / %ae作者名 / email
%scommit 標題%ad / %ar日期 / 相對時間（如 "3 days ago"）
%d分支/tag 標記%cn / %cr提交者名 / 相對提交時間
bash
git log --pretty=format:"%h %ad | %s%d [%an]" --graph --date=short
# 輸出例子：
# * 3f2a1b9 2024-06-10 | 修正登入錯誤 (HEAD -> main) [Chan Tai Man]
# * 9c8d7e6 2024-06-09 | 新增忘記密碼頁 [Lee Siu Ming]

2git show — 睇某一個 commit 嘅詳情

bash
git show                    # 最後一個 commit 嘅詳情＋diff
git show 3f2a1b9            # 指定 commit
git show HEAD~2             # 上兩代
git show v1.0               # tag 都可以
git show 3f2a1b9:src/app.js # 睇嗰個 commit 入面某個檔案嘅完整內容
git show --stat 3f2a1b9     # 只要摘要，唔要 diff
Flag作用
--stat摘要統計取代完整 diff
--name-only / --name-status只列檔名
--oneline / -s（--no-patch）唔顯示 diff，淨係 metadata
--pretty=format:...自訂格式（同 log 一樣）

3git blame — 逐行追究「邊個寫嘅」

bash
git blame app.js             # 每行顯示：commit hash、作者、日期
git blame -L 10,25 app.js    # 淨係睇第 10–25 行
git blame -w app.js          # 忽略空白改動（縮排調整唔再誤導）
git blame -e app.js          # 顯示作者 email（--show-email）
Flag作用
-L <起,止>限定行數範圍（亦支援 -L 10,+5）
-w忽略 whitespace 差異
-M / -C偵測喺檔案內搬過 / 由其他檔案複製過嚟嘅行，追返真正出處
-e / --show-email顯示 email 取代名
--date=relative日期用相對時間
貼士blame 搵到嗰行嘅 commit 之後，用 git show <hash> 睇當時成個改動，先明白「點解」咁寫，唔好淨係睇「邊個」。

4git shortlog — 按作者統計

bash
git shortlog -sn            # 每人 commit 數排行榜（release notes 好用）
git shortlog -sne           # 連 email
git shortlog v1.0..v2.0 -sn # 兩個版本之間
Flag作用
-s / --summary只顯示數目，唔列 commit 標題
-n / --numbered按數量排序（預設按名排）
-e / --email顯示 email

5git reflog — 你嘅救命恩人（記錄 HEAD 去過邊）

reflog 記錄咗 HEAD 嘅每一次移動——包括 commit、checkout、reset、rebase。就算你用 reset --hard 刪咗 commit，reflog 都仲記得佢哋，可以救返。

bash
git reflog                    # 列出 HEAD 嘅移動歷史
git reflog -20                # 淨係最近 20 條
git reflog --date=relative    # 日期用相對時間

# 輸出長咁樣（最左邊係 HEAD@{n} 位置名）：
# 9c8d7e6 HEAD@{0}: reset: moving to HEAD~2
# 3f2a1b9 HEAD@{1}: commit: 新增報表功能      ← 以為冇咗嘅 commit 喺度！
# a1b2c3d HEAD@{2}: checkout: moving from feature to main

實戰：救返 reset --hard 誤刪嘅 commit

➜
bash
git reflog                    # 搵返消失咗嘅 commit hash（例如 3f2a1b9）
git reset --hard 3f2a1b9      # 直接指返去，嘢就返晒嚟
# 或者保守啲，開個分支先睇睇：
git branch rescue 3f2a1b9
記住reflog 係本地嘅，預設保留 90 日（可達嘅）/ 30 日（不可達嘅）。口訣：「喺 Git 度，只要你 commit 過，就好難真係整唔見。」

.gitignore — 叫 Git 唔好追蹤某啲檔案#

喺 repo 根目錄開個叫 .gitignore 嘅檔案，逐行寫規則，Git 就會當嗰啲檔案透明。

規則語法

.gitignore
# 呢行係註解

# 指定檔名（任何目錄層級都會中）
.env
*.log              # 萬用字元 *：所有 .log 檔
temp?.txt          # ?：單一字元

# 指定資料夾（結尾加 /）
node_modules/
dist/
build/

# 只限根目錄（開頭加 /）
/TODO.txt          # 只有根目錄嘅 TODO.txt 中，子目錄嘅唔中

# ** 跨多層目錄
**/logs/debug.log

# 反轉規則（!＝唔好忽略）
*.log
!important.log     # 但 important.log 例外，繼續追蹤
bash
# 檢查某個檔案俾邊條規則擋咗（debug .gitignore 必備）
git check-ignore -v node_modules/express/index.js
# 輸出：.gitignore:5:node_modules/   node_modules/express/index.js
符號意思
*任意數量字元（唔跨 /）
?單一字元
**跨任意層目錄
/ 開頭由 repo 根目錄起計（唔係就任何層級都中）
/ 結尾係資料夾
! 開頭例外：唔好忽略
常見伏位.gitignore 只對未追蹤嘅檔案有效。如果個檔案一早 commit 咗，加落 .gitignore 都冇用，要先 git rm --cached <檔案> 停止追蹤。
貼士想唔污染 repo 嘅 .gitignore，可以用個人專屬忽略檔 .git/info/exclude（唔會被 commit）；想全局忽略（例如 .DS_Store），用 git config --global core.excludesFile ~/.gitignore_global。

git branch / git switch / git checkout — 分支操作#

分支係 Git 最強嘅功能：開一條分支只係「開一個指標」，零成本，放心開。

1git branch — 建立、列出、刪除、改名

➜

開分支唔會切換過去——只係多咗個指標指向 C。要切換先會郁 HEAD。

bash
git branch                      # 列出本地分支（* 號係而家嗰個）
git branch feature              # 由而家位置開新分支
git branch feature a1b2c3d      # 由指定 commit 開
git branch -d feature           # 刪除（安全版：已合併先俾你刪）
git branch -D feature           # 強制刪除（未合併都照刪，小心）
git branch -m old-name new-name # 改名
git branch -M new-name          # 強制改而家分支名（常用：master→main）
Flag作用
-v列出分支＋每個分支最新 commit（verbose）
-vv再顯示追蹤緊邊個遠端分支、領先/落後幾多
-a / --all本地＋遠端追蹤分支全部列出
-r / --remotes只列遠端追蹤分支（origin/main 嗰啲）
-d / --delete刪除已合併分支（未合併會拒絕，保護你）
-D強制刪除（= -d -f）
-m / --move改名（-M 強制）
-c / --copy複製分支（-C 強制）
--merged / --no-merged只列已合併 / 未合併入而家分支嘅分支（大掃除用）
--contains <commit>邊啲分支包含呢個 commit
--sort=-committerdate按最近更新排序
-u origin/main / --set-upstream-to設定/更改追蹤嘅遠端分支
--unset-upstream取消追蹤
貼士季尾大掃除：git branch --merged | grep -v "main" | xargs git branch -d 一次過刪晒已合併嘅分支。

2git switch — 切換分支（Git 2.23+，推薦）

bash
git switch main              # 切去 main
git switch -c feature        # 開新分支兼即刻切過去（create）
git switch -C feature        # 同上，但分支已存在就強制重建
git switch -                 # 返去頭先嗰個分支（超好用！）
git switch --detach a1b2c3d  # 去某個 commit（detached HEAD，見下）
Flag作用
-c <名> / --create建新分支並切換
-C <名> / --force-create強制重建同名分支
-d / --detach切去某 commit（不建分支），進入 detached HEAD
-（參數）上一個分支
-f / --force丟棄工作目錄未 commit 嘅改動強行切換（小心）

3git checkout — 舊式萬用指令（認識吓好）

舊教學成日用 checkout，因為佢一個指令做晒「切分支、還原檔案」兩回事，容易混亂。Git 2.23 起拆咗做 switch（切分支）同 restore（還原檔案），但你仍然要識睇 checkout。

bash
git checkout main            # = git switch main
git checkout -b feature      # = git switch -c feature
git checkout -               # = git switch -
git checkout a1b2c3d         # 去某個 commit（detached HEAD）
git checkout -- app.js       # 丟棄 app.js 工作目錄嘅改動 = git restore app.js
git checkout -- .            # 丟棄全部未暫存改動（危險！）
git checkout HEAD~1 -- app.js  # 由上一個 commit 攞返 app.js 出嚟
留意git checkout -- <檔案> 同 git checkout <分支> 只差一個 --，但一個係還原檔案、一個係切分支。呢個就係點解後來要拆做 switch / restore。

4Detached HEAD — HEAD 直接指住 commit 嘅狀態

小心喺 detached HEAD 狀態做嘅 commit 冇分支指住佢哋，一切走就好快搵唔返（要靠 reflog）。想保留實驗結果，記得即刻開分支：git switch -c my-experiment。

git merge — 合併分支#

合併有兩種結果：Fast-forward（直線推前）同 Merge commit（三路合併）。睇明下面兩幅圖就畢業。

1Fast-forward（預設，當主線冇新 commit）

➜

main 由 B 分支出嚟之後冇郁過，所以 Git 直接將 main 指標「快進」去 D——唔使做任何合併，歷史係一條直線。

2真正嘅三路合併（兩邊都有新 commit）

➜

M 係一個有兩個父 commit（E 同 D）嘅新 commit，記錄咗「呢兩條線喺度合併」。

bash
git switch main
git merge feature                  # 將 feature 合入 main
git merge feature -m "合併登入功能"  # 自訂 merge commit message
Flag作用
--ff（預設）可以 fast-forward 就 fast-forward
--no-ff禁止 fast-forward：一定可以 ff 都照樣開 merge commit，保留「呢度曾經係一條分支」嘅記錄（團隊常用）
--ff-only只接受 fast-forward；唔得就拒絕執行（強迫你 rebase 先，歷史保持直線）
--squash將對方分支全部 commit 壓縮成「工作目錄入面嘅一堆改動」，由你自己開一個普通 commit（對方歷史唔會入嚟）
--abort合併中途（衝突中）放棄，返去合併前狀態
--continue解決完衝突後繼續完成合併
-m "<訊息>"merge commit 嘅 message
--no-edit用預設 message，唔開編輯器
-X ours / -X theirs衝突時自動偏向「我哋」/「佢哋」嗰邊（唔係揀晒全部，只係衝突位自動揀）
-s ours策略：直接當我哋贏晒，完全忽略對方改動（少用）
-v / --verbose顯示詳細合併過程

3衝突（conflict）處理四步曲

兩邊改咗同一檔案嘅同一行，Git 唔敢幫你揀，就會衝突。衝突唔係壞事，係 Git 叫你親自確認。

app.js（衝突標記）
<<<<<<< HEAD
const theme = "dark";       ← 你（main）嘅版本
=======
const theme = "light";      ← 對方（feature）嘅版本
>>>>>>> feature
bash
# 第 1 步：merge 見到 CONFLICT，唔使驚
git merge feature
# Auto-merging app.js
# CONFLICT (content): Merge conflict in app.js

# 第 2 步：睇邊啲檔案衝突
git status          # both modified: app.js

# 第 3 步：手動編輯，刪走 <<<<<<<、=======、>>>>>>> 標記，留返要嘅內容
# （或者一鍵揀邊：）
git checkout --ours app.js     # 全檔案用我哋版本
git checkout --theirs app.js   # 全檔案用佢哋版本

# 第 4 步：標記已解決，完成 merge
git add app.js
git commit                     # 或 git merge --continue

# 中途想放棄成個 merge：
git merge --abort
貼士git config --global merge.conflictStyle zdiff3（或 diff3）會喺衝突標記中間多顯示「合併前原文」，更易判斷。視覺化工具可以用 git mergetool。

git rebase — 改寫歷史嘅利器#

Rebase ＝「將你嘅 commit 剪走，貼去另一個起點上面」。效果係歷史變成一條直線，睇落乾淨好多。

1基本 rebase：將 feature 搬到 main 最新位置

➜

C、D 被「複製」成 C'、D'（內容一樣，hash 唔同），接咗喺 E 後面。之後 main merge feature 就一定係 fast-forward，歷史一條直線。

bash
git switch feature
git rebase main          # 將 feature 搬到 main 最新 commit 之上

# 或者唔使切換，一句搞掂（意思：將 feature rebase 上 main）：
git rebase main feature
Flag / 形式作用
git rebase main將而家分支搬上 main 最新位置
git rebase <基礎> <分支>唔使先 checkout，直接 rebase 指定分支
--onto <新基礎> <舊基礎> <分支>進階搬家：「將 <舊基礎> 之後嘅 commit 搬去 <新基礎> 上面」
-i / --interactive互動模式：改寫、合併、刪除、重排 commit（見下）
--continue解決完衝突後繼續
--skip跳過呢個 commit（解唔到衝突、想放棄佢時）
--abort中途放棄，完全還原到 rebase 之前
--autostash有未 commit 改動時自動 stash，完成後自動還原
--autosquash配 -i：自動排列 fixup! / squash! commit

--onto 範例：搬走其中一段分支

bash
# 情境：feature 由 develop 分出嚟，但你想佢變成由 main 分出
git rebase --onto main develop feature
# 意思：攞「develop..feature」嗰段 commit，貼去 main 上面

2git rebase -i 互動模式 — 整理 commit 歷史

bash
git rebase -i HEAD~3       # 整理最近 3 個 commit（會開編輯器）

編輯器會列出 commit（最舊喺最上面，同 log 倒轉！），你改每行開頭嘅指令字：

rebase 待辦清單例子
pick   a1b2c3d 加入登入表單
reword e4f5g6h 修typo              ← 改 commit message
squash i7j8k9l 登入驗證邏輯         ← 併入上一個（message 會合併）
fixup  m0n1o2p 漏咗個檔             ← 併入上一個（丟棄佢嘅 message）
drop   q3r4s5t debug 用嘅臨時嘢     ← 直接刪除
edit   u6v7w8x 加入測試             ← 停喺度俾你改內容
指令（縮寫）作用
pick（p）照用呢個 commit
reword（r）用呢個 commit，但改 message
edit（e）停低俾你改內容（改完 git commit --amend 再 git rebase --continue）
squash（s）併入上一個 commit，message 兩條合併俾你改
fixup（f）併入上一個 commit，丟棄自己嘅 message
drop（d）刪除呢個 commit
exec（x）喺呢個位置執行 shell 指令（如 exec npm test）

重排：直接上下調換行嘅順序就得。刪走一行＝drop。

貼士配套技巧：git commit --fixup <目標commit> 整一個 fixup commit，之後 git rebase -i --autosquash main 會自動幫你排好位合併。
黃金法則永遠唔好 rebase 已經 push 咗、其他人可能用緊嘅 commit。Rebase 會改寫 hash，隊友嘅歷史會同你分岔，之後 merge 會變災難。口訣：「未 push 先好 rebase。」

rebase vs merge 點揀？

mergerebase
歷史保留真實分支結構（有 merge commit）一條直線，乾淨
改寫歷史唔會會（hash 全變）
衝突解一次逐個 commit 解（可能幾次）
適合合併已完成嘅功能、公開分支本地執靚自己啲 commit 先 push

復原與撤銷：restore / reset / revert / clean#

四個「後悔藥」，藥效唔同、危險程度唔同。睇清楚邊隻啱你而家嘅情況。

快速選擇指南

你想…用危險度
丟棄某檔案未 add 嘅改動git restore <檔案>中（改動真係會冇咗）
將已 add 嘅嘢拎返出暫存區（改動保留）git restore --staged <檔案>低
撤銷最近 commit，保留改動喺工作目錄git reset --soft/--mixed HEAD~1低-中
撤銷最近 commit，改動都唔要git reset --hard HEAD~1高
撤銷已 push 嘅 commit（安全做法）git revert <commit>低
刪走 untracked 檔案（node_modules 重建嗰類）git clean -fd高

1git restore — 還原檔案（Git 2.23+）

bash
git restore app.js                    # 丟棄 app.js 工作目錄嘅改動（用暫存區版本覆蓋）
git restore .                         # 丟棄全部未暫存改動
git restore --staged app.js           # 將 app.js 拎出暫存區（unstage，改動保留喺工作目錄）
git restore --staged --worktree app.js  # 暫存區＋工作目錄都還原去 HEAD
git restore --source=HEAD~2 app.js    # 由兩代前嘅 commit 攞返 app.js 出嚟
git restore -p app.js                 # 互動模式：逐塊揀還唔還原
Flag作用
--staged / -S還原暫存區（預設來源係 HEAD）
--worktree / -W還原工作目錄（預設行為；預設來源係暫存區）
--source=<commit> / -s指定由邊個 commit 攞版本
-p / --patch互動逐塊揀

對照舊寫法：git checkout -- app.js ≈ git restore app.js；git reset HEAD app.js ≈ git restore --staged app.js。

2git reset — 移動分支指標（三種模式）

reset 做嘅嘢係「將而家分支（連 HEAD）指去另一個 commit」。三個模式分別在於：郁完之後，暫存區同工作目錄跟唔跟住郁。

bash
git reset --soft HEAD~1      # 撤銷 commit，改動留喺暫存區（最溫柔）
git reset HEAD~1             # = --mixed：撤銷 commit，改動變返未暫存
git reset --hard HEAD~1      # 撤銷 commit，改動全部丟棄（最粗暴）
git reset --hard HEAD        # 唔郁指標，只係丟棄晒工作目錄＋暫存區改動
git reset a1b2c3d            # 返去指定 commit（mixed）
git reset app.js             # 只將 app.js 拎出暫存區（= restore --staged）
Flag / 形式作用
--soft只郁分支指標
--mixed（預設）郁指標＋重設暫存區
--hard郁指標＋重設暫存區＋重設工作目錄
--keep類似 hard，但有未 commit 改動同目標有衝突時會拒絕（保護改動）
HEAD~<n>上 n 代 commit
<檔案>（不連模式）檔案層級：只 unstage，唔郁指標
-q靜音
危險reset --hard 係少數真係會整唔見嘢嘅指令（未 commit 嘅改動救唔返）。已 commit 嘅就可以靠 git reflog 搵返。已 push 嘅 commit 唔好用 reset，要用 revert。

3git revert — 安全撤銷（開個「反向 commit」）

reset 係「時光倒流改寫歷史」，revert 係「開一個新 commit 做相反嘅改動」——歷史唔變，所以 push 咗嘅嘢都用得。

VS
bash
git revert HEAD              # 撤銷最後一個 commit
git revert a1b2c3d           # 撤銷指定 commit
git revert HEAD~3..HEAD      # 撤銷最近 3 個（每個開一個 revert commit）
git revert --no-commit HEAD  # 改動放落暫存區但唔即刻 commit，俾你一次過 commit 幾個 revert
git revert -m 1 a1b2c3d      # 撤銷 merge commit（-m 1 指定以第一父線為主）
Flag作用
-e / --edit（預設）開編輯器改 revert message
--no-edit用預設 message 唔開編輯器
-n / --no-commit只將反向改動放入暫存區，唔自動 commit
-m 1 / --mainline 1revert merge commit 時必填：以邊條父線為「主線」
--continue / --abort衝突時繼續 / 放棄

4git clean — 清除 untracked 檔案

bash
git clean -n          # 預演：列出會刪咩（一定要做嘅步驟！）
git clean -f          # 刪 untracked 檔案（force）
git clean -fd         # 連 untracked 資料夾都刪
git clean -fx         # 連 .gitignore 忽略咗嘅都刪（node_modules 都會冇埋）
git clean -fdx        # 最深層大掃除＝回到「啱啱 clone」嘅狀態
git clean -i          # 互動模式逐個揀
git clean -n -e "*.log"  # 預演時排除某 pattern
Flag作用
-n / --dry-run預演，唔真係刪（落 -f 之前必做）
-f / --force真係刪（冇 -f 預設會拒絕執行）
-d連資料夾都處理
-x連被 ignore 嘅檔案都刪
-X只刪被 ignore 嘅檔案（保留一般 untracked）
-i / --interactive互動模式
-e <pattern> / --exclude排除某 pattern
危險clean 刪嘅係 untracked 檔案——即係 Git 從來冇記錄過，reflog 都救唔返。永遠先 git clean -n 預演，確認無誤先落 -f。

遠端協作：remote / fetch / pull / push#

四個指令嘅分工：remote 管理連線、fetch 只下載資訊、pull 下載兼合併、push 上傳。

1git remote — 管理遠端連線

bash
git remote                    # 列出遠端名（通常得 origin）
git remote -v                 # 連 URL 一齊列（verbose，好常用）
git remote add origin https://github.com/user/repo.git   # 加遠端連線
git remote add upstream https://github.com/original/repo.git  # fork 後加原作者個 repo
git remote rename origin old-origin
git remote rm upstream
git remote set-url origin git@github.com:user/repo.git   # HTTPS 轉 SSH
git remote show origin        # 詳細資訊：邊個分支追蹤邊個
子指令 / Flag作用
-v / --verbose顯示 fetch 同 push 嘅 URL
add <名> <url>新增遠端
rm <名> / remove移除遠端連線（遠端追蹤分支都會刪）
rename <舊> <新>改名
set-url <名> <url>改 URL
get-url <名>睇 URL
show <名>詳細報告（分支對應、push/pull 設定）
prune <名>清走「遠端已刪、你仲留低」嘅追蹤分支

2git fetch — 只下載，唔郁你嘅嘢（安全！）

fetch 只會更新「遠端追蹤分支」（origin/main 嗰啲唯讀副本），你嘅工作目錄同本地分支完全唔郁。想知人哋改咗咩，先 fetch 再慢慢睇。

➜
bash
git fetch                  # 由 origin 更新所有追蹤分支
git fetch upstream         # 由指定遠端更新
git fetch --all            # 所有遠端一齊更新
git fetch --prune          # 順便清走遠端已刪嘅追蹤分支（建議常開）
git fetch -v               # verbose：顯示邊個分支有更新
git fetch --dry-run        # 預演

# fetch 之後想睇人哋改咗咩：
git log HEAD..origin/main --oneline    # 遠端有但你冇嘅 commit
git diff HEAD...origin/main            # 具體改動
Flag作用
--all所有 remote 都 fetch
--prune / -p同步刪除本地已失效嘅遠端追蹤分支
--tags / -t連所有 tag 都 fetch
-v / --verbose詳細輸出
--dry-run預演
--depth=<n>（淺 clone 用）加深歷史
--unshallow將淺 clone 補返成完整歷史
貼士想長期自動 prune：git config --global fetch.prune true。

3git pull ＝ fetch ＋ merge（預設）

bash
git pull                    # = git fetch + git merge origin/main
git pull --rebase           # = git fetch + git rebase origin/main（歷史直線）
git pull --ff-only          # 只接受 fast-forward，否則拒絕（最保守）
Flag作用
--rebase / -r用 rebase 代替 merge 整合
--no-rebase明確用 merge（覆蓋 config）
--ff-only唔係 fast-forward 就拒絕（逼你先 rebase）
--ff可以 ff 就 ff（預設行為）
--autostash有未 commit 改動時自動 stash 再還原
-v / --verbose、-q / --quiet詳細 / 靜音
--all由所有 remote pull
貼士想 git pull 永遠用 rebase：git config --global pull.rebase true。想永遠只准 ff：git config --global pull.ff only。

4git push — 上傳你嘅 commit

bash
git push                        # 推去已設定嘅 upstream
git push origin main            # 明確指定：遠端 origin，分支 main
git push -u origin main         # 第一次推新分支：-u 順手設定追蹤關係
git push origin feature:main    # refspec：本地 feature 推去遠端 main（少用）
git push --tags                 # 連所有 tag 一齊推
git push origin --delete old-branch   # 刪遠端分支
git push origin :old-branch     # 同上（舊寫法：推「空」過去＝刪除）
➜
Flag作用
-u / --set-upstream推之餘設定追蹤關係，之後 git push / git pull 唔使再寫參數
--force / -f強制覆蓋遠端歷史（危險，見下）
--force-with-lease「有條件」強推：遠端俾人更新過就拒絕（安全版 -f，推薦）
--tags連所有本地 tag 推埋
--follow-tags只推「指向已推 commit」嘅 annotated tag
--delete <分支>刪遠端分支
--all推晒所有本地分支
-n / --dry-run預演，唔真係推
-v / --verbose、-q詳細 / 靜音
危險push --force 會冇條件覆蓋遠端：如果隊友啱啱 push 咗新 commit，會俾你直接冚走。
改用 --force-with-lease：Git 會檢查「遠端而家嘅狀態係咪同你預期一樣」，唔一樣就拒絕——rebase / amend 完要重推時必用。
再加 git config --global push.useForceIfIncludes true 會更穩陣。
注意push 俾人拒絕（non-fast-forward）＝遠端有你冇嘅 commit。正確做法：git pull --rebase 整合先，再 push。

git stash — 暫時收埋手頭上嘅改動#

寫到一半要切分支救火？stash 幫你將未 commit 嘅改動收埋，搞掂先拎返出嚟。

bash
git stash                       # 收埋改動（已追蹤檔案）
git stash push -m "做到一半嘅登入"  # 加埋註解，list 嗰陣易認
git stash -u                    # 連 untracked 新檔都收埋
git stash -a                    # 連 ignore 咗嘅檔都收埋（all）
git stash list                  # 睇有幾多層
git stash show                  # 最頂嗰層改咗邊啲檔案（摘要）
git stash show -p stash@{1}     # 睇完整 diff
git stash pop                   # 拎返最頂嗰層，兼由 stash 刪走
git stash apply stash@{1}       # 拎指定嗰層，stash 保留
git stash drop stash@{1}        # 刪走指定嗰層
git stash clear                 # 清空成個 stash
git stash branch hotfix         # 由 stash 開條新分支（攞唔返嚟時嘅救星）
git stash -p                    # 互動模式：揀住收邊啲 hunk
子指令 / Flag作用
push -m "訊息"stash 兼加描述
-u / --include-untracked連 untracked 檔案
-a / --all連被 ignore 嘅檔案
-p / --patch互動揀 hunk
-k / --keep-index已暫存嘅嘢唔郁，只 stash 未暫存部分
list列出所有 stash
show [-p]睇內容（-p 顯示 diff）
pop vs applypop 用完即刪；apply 保留 stash 副本
branch <名>以 stash 內容開新分支
drop / clear刪一層 / 全刪
伏位隔咗幾個星期先 apply 舊 stash，檔案可能已大改而出現衝突——解完衝突後 stash 唔會自動 drop，要手動 git stash drop。

git tag — 幫重要時刻打上標記#

Tag ＝ 永不移動嘅分支指標，多數用嚟標版本號（v1.0.0 之類）。分「輕量」同「附註」兩種。

bash
git tag v1.0                      # 輕量 tag（淨係個名）
git tag -a v1.0 -m "首個正式版"     # 附註 tag（推薦：有 message）
git tag -a v1.1 a1b2c3d -m "修補版" # 幫舊 commit 補打 tag
git tag                           # 列出所有 tag
git tag -l "v1.*"                 # pattern 篩選
git tag -n                        # 連註解一齊列出
git show v1.0                     # 睇 tag 指向嘅 commit ＋ tag 資訊
git tag -d v0.9                   # 刪本地 tag
git push origin v1.0              # 推單個 tag 上遠端
git push --tags                   # 推晒所有 tag
git push origin --delete v0.9     # 刪遠端 tag
git checkout v1.0                 # 去嗰個版本（detached HEAD）
git switch -c hotfix-v1.0.1 v1.0  # 由 tag 開分支做修補
Flag作用
-a / --annotate建立附註 tag（有 message、作者、日期）
-m "訊息"tag 訊息（唔加會開編輯器）
-l "pattern" / --list篩選列出
-n列出時顯示註解頭一行
-d / --delete刪除本地 tag
-f / --force強制覆蓋已存在嘅 tag 名
-s / --signGPG 簽名 tag
-v <tag> / --verify注意：呢度 -v 係「驗證簽名」，唔係 verbose！
--sort=-version:refname按版本號排序（新→舊）
注意預設 git push 唔會推 tag，要明確 git push origin <tag> 或 --tags。

進階指令：cherry-pick / bisect / worktree / submodule#

未必日日用，但關鍵時刻好救命。

1git cherry-pick — 摘某一個 commit 過嚟

➜
bash
git cherry-pick a1b2c3d        # 摘一個 commit 入嚟而家分支
git cherry-pick A..E           # 摘 A 之後到 E 嘅連續範圍（唔包 A）
git cherry-pick -n a1b2c3d     # --no-commit：改動放入暫存區，唔即刻 commit
git cherry-pick -x a1b2c3d     # message 尾自動加 "(cherry picked from ...)" 方便追溯
git cherry-pick -e a1b2c3d     # 開編輯器改 message
git cherry-pick -m 1 a1b2c3d   # 摘 merge commit（-m 指定主父線）
git cherry-pick --continue     # 解完衝突繼續
git cherry-pick --abort        # 放棄

2git bisect — 對分搜尋搵「邊個 commit 引入咗個 bug」

100 個 commit 入面有一個引入咗 bug，逐個 checkout 要試 100 次；bisect 用對分搜尋，log₂(100) ≈ 7 次就搵到。

bash
git bisect start               # 開始
git bisect bad                 # 而家 HEAD 係壞嘅
git bisect good v1.0           # v1.0 係好嘅
# → Git 自動 checkout 中間 commit，你測試完答：
git bisect good                # 呢個好 → 範圍縮一半
git bisect bad                 # 呢個壞 → 範圍縮另一半
# ...重複幾次，Git 話你知 "xxx is the first bad commit"
git bisect reset               # 完事，返返去原來分支

# 懶人全自動版：寫個測試 script，exit 0 = good，非 0 = bad
git bisect run npm test
git bisect log                 # 睇返成個搜尋過程

3git worktree — 一個 repo 同時開幾個工作目錄

想一邊寫 feature、一邊改 main 嘅 urgent bug，唔想 stash 嚟 stash 去？worktree 俾你同一個 repo 喺唔同資料夾 checkout 唔同分支。

bash
git worktree add ../hotfix-dir hotfix-branch   # 開個新資料夾裝住另一條分支
git worktree list                              # 列出所有 worktree
cd ../hotfix-dir                               # 入去就係另一條分支嘅世界
git worktree remove ../hotfix-dir              # 用完刪走
git worktree prune                             # 清理手動刪咗嘅殘留記錄
貼士跑慢吞吞嘅測試嗰陣，開個 worktree 喺隔籬資料夾繼續做嘢，唔使等。

4git submodule — repo 入面巢狀另一個 repo

bash
git submodule add https://github.com/lib/lib.git vendor/lib   # 加入子模組
git commit -m "加入 lib 子模組"
# 其他人 clone 完，子模組係空嘅，要：
git submodule init                 # 初始化
git submodule update               # 下載內容
git submodule update --init --recursive   # 一句搞掂（多層巢狀都包）
# 或者 clone 嗰陣一步到位：
git clone --recurse-submodules <url>

附錄：HEAD~ vs HEAD^、兩點 vs 三點#

1~（tilde）同 ^（caret）嘅分別

兩個都係「相對定位」：~n 沿主線向上行 n 代；^n 揀第 n 個父 commit（merge commit 先有多個父）。

2A..B 同 A...B 嘅分別

用喺A..B（兩點）A...B（三點）
git logB 有、A 冇嘅 commit兩邊各自獨有嘅 commit（對稱差集）
git diff直接比較 A 同 B 兩點比較「分岔點（merge base）」同 B —— 即「B 呢條分支帶嚟嘅改動」
bash
git log main..feature --oneline    # feature 有、main 冇嘅 commit（PR 入面嘅嘢）
git log main...feature --oneline   # 兩邊各自新嘅 commit
git log --left-right --oneline main...feature   # 用 < / > 標示嚟自邊邊
git diff main...feature            # 睇 feature 分支帶嚟嘅改動（推薦）
git diff main..feature             # 連 main 自己新加嘅嘢嘅「反向」都包埋，易誤會

Cheat Sheet 速查表#

打印出嚟貼喺檯頭都得。按情境搵指令。

情境 → 指令

  • 新開 repo：git init -b main
  • 複製遠端 repo：git clone <url>
  • 睇狀態：git status -sb
  • 暫存改動：git add -A / 揀住加 git add -p
  • 提交：git commit -m "訊息"
  • 改上一個 commit：git commit --amend
  • 睇歷史：git log --oneline --graph --all
  • 睇改動：git diff / git diff --staged
  • 開分支兼切換：git switch -c <名>
  • 切分支：git switch <名> / 返上個 git switch -
  • 合併：git merge <分支>（保歷史 --no-ff）
  • 更新分支起點：git rebase main
  • 整理 commit：git rebase -i HEAD~3
  • unstage：git restore --staged <檔案>
  • 丟棄檔案改動：git restore <檔案>
  • 撤銷 commit 留改動：git reset --soft HEAD~1
  • 撤銷 commit 唔要改動：git reset --hard HEAD~1
  • 安全撤銷已 push commit：git revert <commit>
  • 刪 untracked 檔：git clean -nd 先預演
  • 睇遠端：git remote -v
  • 下載遠端資訊：git fetch --all --prune
  • 拉落嚟合併：git pull --rebase
  • 推上去：git push -u origin <分支>
  • rebase 後重推：git push --force-with-lease
  • 收埋手頭嘢：git stash -u -m "訊息"
  • 拎返出嚟：git stash pop
  • 打版本標記：git tag -a v1.0 -m "訊息"
  • 推 tag：git push origin v1.0
  • 搵邊個寫嘅：git blame -L 10,20 <檔案>
  • 救返誤刪 commit：git reflog → git reset --hard <hash>
  • 搵引入 bug 嘅 commit：git bisect start
  • 摘單個 commit：git cherry-pick <hash>
  • 唔記得點用：git <指令> -h / git help <指令>

每日工作流（feature branch flow）

bash
# 1. 由最新 main 開分支
git switch main && git pull --rebase
git switch -c feature/login

# 2. 做嘢，密密 commit
git add -p && git commit -m "加入登入表單"

# 3. push 前執靚歷史（本地未 push 先做！）
git rebase -i main

# 4. 推上遠端開 PR
git push -u origin feature/login

# 5. PR 合併後清理
git switch main && git pull --prune
git branch -d feature/login
git push origin --delete feature/login   # 遠端分支都刪埋
最後一句Git 心法：密密 commit、慢慢 push。本地 commit 係免費嘅安全網——有 reflog 喺度，大膽試都得。
